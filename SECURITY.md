# Security Policy

Orbit parses untrusted input from the network — HTTP/1.1, HTTP/2, HTTP/3 and
QUIC framing, WebSocket frames, multipart bodies, and TLS handshakes — and does
so over raw kernel I/O interfaces. Security reports are taken seriously.

## Supported Versions

| Version | Supported |
|---------|-----------|
| 1.4.x   | ✅ Security fixes provided |
| < 1.4   | ❌ Please upgrade |

Orbit is pre-stable software maintained by a small team. Only the latest minor
release receives fixes; there are no long-term support branches.

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues,
pull requests, or discussions.**

Report privately through one of:

1. **GitHub Security Advisories** (preferred) — open
   <https://github.com/varuns2903/orbit-framework/security/advisories/new>.
   This creates a private thread visible only to maintainers.
2. **Email** — `04varuns@gmail.com` with `[SECURITY]` in the subject line.

Please include as much of the following as you can:

- The type of issue (buffer overflow, use-after-free, request smuggling,
  authentication bypass, denial of service, …)
- Affected version or commit hash
- Affected source files and, where you know it, the specific function
- Build configuration — compiler, CMake options, which `ORBIT_ENABLE_*`
  subsystems were on
- Step-by-step reproduction instructions, ideally a minimal `main.cpp` plus the
  bytes sent to the server
- Proof-of-concept or exploit code, if you have it
- Your assessment of the impact

Reports written in English are easiest for us to act on quickly.

## What to Expect

| Stage | Target |
|-------|--------|
| Acknowledgement of your report | within 72 hours |
| Initial assessment and severity | within 7 days |
| Fix or mitigation plan communicated | within 14 days |
| Public disclosure | after a fix ships, coordinated with you |

We will keep you updated as the fix progresses, and we will credit you in the
advisory and changelog unless you ask us not to.

## Disclosure Policy

We follow coordinated disclosure. We ask that you give us a reasonable window
to ship a fix before publishing details. We will not pursue legal action
against researchers who follow this policy and act in good faith.

## Scope

In scope:

- Memory-safety bugs in the event loop, protocol parsers, or QUIC stack
- HTTP request smuggling, response splitting, or desynchronisation
- Authentication or authorisation bypass in bundled middleware (JWT, OAuth2,
  CSRF, session management, rate limiting)
- Path traversal in the static file middleware or reverse proxy
- TLS misconfiguration that weakens connection security by default
- Remotely triggerable crashes, infinite loops, or unbounded allocation

Out of scope:

- Vulnerabilities in third-party dependencies — report those upstream, though we
  appreciate a heads-up so we can bump the pinned version
- Issues that require a misconfiguration explicitly warned against in the docs
- Denial of service that requires privileged local access
- Missing hardening that is documented as the application's responsibility
- Reports generated by automated scanners without a demonstrated impact

## Known Security Considerations

These are documented limitations, not undisclosed vulnerabilities. See
[docs/loopholes_and_drawbacks.md](docs/loopholes_and_drawbacks.md) for the full
discussion.

- **Custom protocol parsers.** Orbit implements its own HTTP header, multipart,
  and WebSocket parsers rather than delegating to a hardened third-party
  library. This is a deliberate performance trade-off and a correspondingly
  large attack surface. The HTTP parser is fuzzed nightly in CI.
- **Coroutine lifetimes.** Async database and I/O paths use C++20 coroutines.
  A request context destroyed before a suspended coroutine resumes is a
  use-after-free. Reports in this area are especially welcome.
- **Development certificates.** `cert.pem` / `key.pem` referenced in examples
  and docs are self-signed development material generated locally. They are
  gitignored and are not distributed with Orbit. Never deploy with them —
  generate your own, and see [docs/deployment.md](docs/deployment.md) for
  terminating TLS in production.
- **Defaults.** TLS, rate limiting, CSRF, and body-size limits are opt-in
  middleware, not defaults. Deploying Orbit without them is deploying an
  unhardened server. See [docs/deployment.md](docs/deployment.md).
